# Q26: What each absence means

**Fixture status:** Examples are provisional until verified against the selected frozen snapshot, pinned BOR release, or versioned retrieval cache, as applicable. Existing local checks retain their stated query dates; they are not a frozen acceptance baseline. See [expected-answer policy](../roadmap.md#expected-answer-policy).

## Question

> For this address, which sources hold no record (HPD registration, DOS entity, either layer, any violation), and what does each absence mean?

### Sub-questions

CLaRO-style cleanup (stage 1, 2026-11-19). The parent asks, for one lot, which of five sources hold nothing and why. No new graph element and no loader: lots (`hpdRegistered`), owner contacts, `DosEntity` (Q5), layer membership and absence codes (Q8, Q9) and `Violation` (Q15) exist. Absences are computed at answer time, not stored. The parent passes when all four pass.

| ID | Sub-question | Answer requirements covered |
| --- | --- | --- |
| Q26.1 | Does the HPD registration data hold a record for this lot, and if not, why? | source, snapshot date, reason |
| Q26.2 | Does the DOS active-entity snapshot hold a record for the lot's owner entity, and if not, why? | source, snapshot date, reason |
| Q26.3 | Is the lot in each layer (Operational Network, Owner Portfolio), and if not, why, with recall stated as unmeasured? | source, snapshot date, reason, recall |
| Q26.4 | Does the graph hold any HPD violation for the lot, and what does none mean? | source, snapshot date, reason, caveat |

### Hidden assumptions made explicit (profiled 2026-11-19)

| Assumption | Rule |
| --- | --- |
| The five reasons | BOR's five top-level reasons (scheme `network-absence-reasons`) are used for every source, so the answer has one vocabulary. Q26 applies them to the non-layer sources by the rules below (decision 2026-11-19) |
| Registration (Q26.1) | No row for the lot: `outside_source_coverage` (detail `no_registration`). Whether the lot is exempt or unregistered is not known and the answer says so. A lot outside the rental scope (unregistered, under 3 units) is not in the graph and has no answer |
| DOS entity (Q26.2) | Looked up by the N3 key of each owner corporation name. A record under any name: present. Names looked up and none found: `no_qualifying_linkage`, with the spellings tried (a long-form DOS name is a Q22 lead, not a match; anchors C and D). No owner contact, or only a person: `outside_method_input` (no entity name to look up). Only active New York entities are held, so a non-New York entity is a Q25 retrieval lead |
| Layers (Q26.3) | The lot's group, or BOR's top-level reason and detail code. Both reasons can differ for one lot (20 River Terrace: network member, portfolio `excluded_by_policy` / `coop_condo_dominated`). Recall is unmeasured: a non-link is not a finding of different owners |
| Violations (Q26.4) | Violations are loaded for HPD-registered lots only (Q15). A registered lot with none: `outside_source_coverage`, meaning none in the snapshot (2026-07-02), not good conditions. An unregistered lot is `not-loaded`, never "none": the source holds violations for such lots (4064820003: 219). This is an outcome, not one of the five reasons, as an unavailable source is never an answer about the data |
| Snapshot dates | Registration 2026-05-29, DOS 2026-07-06, violations 2026-07-02, layers release v0.3.0 (run `2026-05-29-869bd299`), PLUTO 26v1. Later public records are a freshness limit |

## Who asks and why

"Nothing found" means different things, and an organizer should not read it as "nothing there".

## Required content of an answer

For each source with no record: the source, its snapshot date, and one reason:
- no qualifying linkage
- excluded by policy
- below the eligibility rule
- outside source coverage
- outside method input

The answer also says recall is unmeasured where it applies.

## Caveats the answer must carry

- Absence from a snapshot is not a finding about the world.
- No violation record means none in the snapshot, not that conditions are good.
