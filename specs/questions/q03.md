# Q3: Deed grantee against HPD owner

## Question

> Who is the grantee on the most recent ACRIS deed for this lot, and does the deed name the same party as the HPD registration, compared by exact normalized name?

### Sub-questions

CLaRO-style cleanup (stage 1, step 1). The parent is compound: it asks for a recent document, the parties on it, the registered owner, and a comparison. It is split into atomic questions, with identifiers, source names and column vocabulary removed from the text. The comparison results are not stored; they are computed at answer time over stored values (Q3.4, Q3.5). Tests and ontology fragments reference these IDs. Q3 keeps its ID and passes when all five pass.

| ID | Sub-question | Answer requirements covered |
| --- | --- | --- |
| Q3.1 | Which document transferring title was most recently recorded against this lot, and what are its dates and amount? | 1 (deed, dates, amount), 5 (snapshot date) |
| Q3.2 | Who is named as receiving title on that document? | 1 (every grantee) |
| Q3.3 | Who is recorded as the owner on the registrations of this lot's buildings? | 2 (registered owner). Answered by Q2.2 through the lot's buildings; no new graph element |
| Q3.4 | Does each party receiving title carry the same name as a recorded owner, under a stated comparison rule? | 3 (name agreement) |
| Q3.5 | Is the address given for each party receiving title the same as the address given for the recorded owner? | 4 (address agreement) |

### Hidden assumptions made explicit

| Assumption in the original wording | Rule (where settled) |
| --- | --- |
| "the deed" is one kind of document | Several document types transfer title (a plain deed, correction deeds, deeds with a life estate and others). Which count is a decision, and it changes the answer for about 8,500 of 181,863 registered lots (queried 2026-11-12). See `specs/decisions.md` |
| "most recent" has one answer | "Latest recorded date" is the rule (caveat). 4,928 registered lots have two or more deeds recorded on their latest date. All tied deeds are returned and none is chosen (Q3.1) |
| A deed belongs to one lot | A deed can name many lots (8,031 of 160,873 latest deeds). The deed is reported with its other lots as a count, never as lot-specific (Q3.1) |
| "when" has a document date | The document date is missing on 56,929 of the 1,003,931 deeds in scope. The recorded date is the rule and the document date is reported only when present (Q3.1) |
| The amount is the price | An amount of 0 is common and does not mean a free sale. Reported as recorded; the answer does not call a deed a sale (Q3.1) |
| "the grantee" is one party | A deed can name several parties receiving title; all are listed (Q3.2) |
| "the HPD registration" is one registration | A lot's buildings have their own registrations, each with several owner contacts (Q2). Q3.3 lists them all and none is chosen |
| "the same party" follows from the same name | Name agreement is a recorded string comparison, not a finding (caveat). The rule is stated with the result (Q3.4) |
| "exact normalized" has a defined rule | Not yet defined (CLAUDE.md open point). Settled in this stage (`specs/decisions.md`). A difference of spacing is a difference under the exact rule (anchor G) |
| Address agreement has a source for both sides | Owner contact addresses are not in the Q2 graph; they are added for Q3.5. The address can be absent on either side, and a shared address at a mail drop is not evidence |
| Deed and registration describe the same date | They are different snapshots (2026-05-29 and 2026-05-31) and different moments. The answer carries both dates and does not infer which is newer |

### Decisions that set the rules (2026-11-12)

- **Deed types:** DEED, DEED TS, DEED LE, DEED RC, DEEDO, DEEDP, CORRD and CONDEED. DEED COR (an index-correction code for office use) is not a deed. The official descriptions are in `data/sources.yaml`.
- **Name rules:** N1 (uppercase, trim, collapse whitespace) gives an exact normalized match. N2 (N1, remove periods, commas to spaces) gives a normalization match, reported with the rule. Spaces inside a name are never removed, so anchor G stays a difference. Anything else is different; an absent name is not comparable.
- **Address rule A1:** same = street line equal after N1 and the first five ZIP digits equal; differs; absent. The second line is reported apart. Abbreviations are differences.
- **Graph scope:** every deed on an in-scope lot, with its grantees. Grantors are not loaded. The comparison results are computed at answer time and not stored.

## Who asks and why

A mismatch is the first sign that the party holding the deed and the party registered with HPD may differ.

## Required content of an answer

1. The most recent deed for the lot (document id, document date, recorded date, amount) and **every** grantee on it.
2. The HPD-registered owner name (as in Q2).
3. **Name agreement**, reported as one of: exact normalized match, normalization match (with the rule id), or different.
4. **Address agreement**, reported as one of: same, differs, or absent. The unit is reported apart from the match.
5. The snapshot dates of both sources.

## Answer contract

| Field | Concept | Rule |
| --- | --- | --- |
| `bbl` | BBL | The lot asked about |
| `deeds` | deed | The deed(s) with the latest recorded date. All that tie are returned, none chosen. Empty means "no deed in the snapshot", not that the lot never changed hands |
| `deeds[].documentId`, `docType`, `docDate`, `recordedDate`, `amount` | document id, document type, document date, recorded date, document amount | As recorded. `docDate` is absent when ACRIS has none. `amount` 0 is reported as recorded, never as a free sale |
| `deeds[].otherLots` | has deed | How many other graph lots the deed names, so a multi-lot deed is not read as lot-specific |
| `deeds[].grantees` | grantee | Every grantee: `name`, `mailingAddress`, `addressLine2`, `zip`, as recorded (absent when blank) |
| `owners` | registered owner contact | The Q2 owners on the registrations of the lot's buildings, with `mailingAddress`, `addressLine2`, `zip`. None chosen |
| `nameAgreement` | name agreement | One entry per grantee and owner pair: `outcome` (exact normalized, normalization match, different, not comparable) and `rule` (N1 or N2) |
| `addressAgreement` | address agreement | One entry per pair: `outcome` (same, differs, absent), `rule` A1, and the two second lines apart |
| `snapshots` | none | The ACRIS and HPD snapshot dates (2026-05-31 and 2026-05-29) |

## Caveats the answer must carry

- Exact agreement is a recorded comparison of strings. The answer does not say "same party" on name agreement alone.
- Address agreement at a mail-drop address is flagged as non-evidence.
- A near match is not a finding (see Q22).
- "Most recent" means latest recorded date, not document date.
